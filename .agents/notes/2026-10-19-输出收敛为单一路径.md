# 决策：输出收敛为单一路径参数（2026-10-19）

状态：生效

## 问题

输出位置有三个参数：`output`（完整文件路径）、`folder`（相对输出根的分类子目录）、`output_dir`（输出根，绝对路径），
顶层与任务级各一份，共 6 个 schema 字段、3 段长描述。

但实际上只有两件事：

- 我要指定到**文件**。
- 我要指定到**文件夹**。

`folder` 与 `output_dir` 的区别不是语义区别，只是**路径写法的区别**（相对 vs 绝对）。
同一个概念被拆成两个参数，只因为写法不同——这是臃肿的根因。

## 决策

只留 `output`，一个路径覆盖全部场景，按形态判断：

```text
省略                          → 默认根，自动命名
末尾是 / 或 \                 → 文件夹（显式，优先级最高）
扩展名是图片扩展名            → 文件
其它                          → 文件夹
```

`folder` 与 `output_dir` 删除，不做兼容层。

## 为什么不是别的判据

- **不用尾斜杠做主要判据**：Windows 上编辑器常吃掉尾斜杠，判错时会把文件夹变成一张叫 `兔子.png` 的图。
- **不用「有扩展名就算文件」**：`E:/图/v1.2` 这类目录名会中招。只认图片扩展名，`v1.2` 就落回文件夹。
- **不用「文件/目录」两个参数**：那是把同一个路径拆两次，回到原点。

扩展名在这里只承担「文件还是文件夹」的职责。真实格式仍由字节魔数决定，所以调用方写 `.png` 而收到 JPEG 也不会出错——两个职责不重叠。

判错时代的价有界：最坏是多出一个文件夹，不会把你的文件夹变成一张图。

## 替代方案（否决）

- **保留三参数只改文档**：概念数没变，agent 仍然要记三套规则。
- **只留 output + name**：回到「目录与文件名拆两处」，`n` 派生还要再拼一次。
- **只留目录、文件名全自动**：删掉了「落盘即用、不用批量重命名」这个既有能力。
- **显式报错拦截旧参数**：与「直接丢弃、不做兼容」的要求冲突，旧调用会静默落到默认目录（已在架构防错清单记录该风险）。

## 影响

- schema 字段 6 → 2（顶层与任务级各一个 `output`）。
- 破坏性变更：`folder` 与 `output_dir` 不再生效，传了也不会报错，只会被忽略。版本升 0.9.0。
- 相对路径按输出根解析并禁止爬出，与上一版一致。
- `info` 的 `output` 段改成「一条规则 + 五种写法」的对照表，并新增 `examples` 段直接给可抄的调用。
