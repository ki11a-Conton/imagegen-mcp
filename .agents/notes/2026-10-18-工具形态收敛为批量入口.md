# 决策：工具形态收敛为单一批量入口（2026-10-18）

状态：生效

## 问题

原先是 `generate_image` 与 `edit_image` 两个工具，各自单次执行。
要并发跑多张图，调用方只能派多个子 agent 分别调用；而多个 agent 同时写同一目录会撞名。

## 决策

两个工具合并为一个 `create_images`，参数是 `jobs` 数组。

- 每个任务带 `images` 就走 `/images/edits`，不带就走 `/images/generations`，调用方不判断接口。
- 进程内固定 worker 池并发，默认 3 路，上限 6。
- 顶层参数作为所有任务的默认值，任务级同名字段覆盖。
- 单个任务失败收敛成 `{ ok: false }`，不中断整批。

## 替代方案（强制）

- 保留两个工具、各自加 `jobs` 数组：两套 schema 与两段几乎相同的执行逻辑，维护成本翻倍，且调用方仍要自己判断该用哪个。
- 拆成三个工具（gen / edit / batch）：schema 与路由判断都外推给调用方，agent 更容易误用。
- 靠外部脚本并发起多个 MCP 进程：进程间无法共享并发上限，撞名与限流都失控。

## 影响

- 工具面从 3 个降到 2 个，agent 的选择成本降低。
- 并发上限收敛到进程内一处，容易调。
- 破坏性变更：旧工具名不再存在，调用方需迁移。
